## MF-01: Hardcoded Decision Literal (22 / 44 / 73) in Benchmark Visualization Export

### 1. Incident Description
In Wave H.3, the interactive HTML dashboard (`docs/BENCHMARK_DASHBOARD.html:661-664`) presented the following decision breakdown for the primary defense (Arm R) on attack inputs:
- `ALLOW`: 22
- `FLAG`: 44
- `BLOCK`: 73
- Resulting Strict Recall: 73 / 139 = **52.52%**

However, re-derivation from the evaluated predictions file (`results/final-v4/predictions.jsonl`, SHA-256 `74e0975eccda...`) reveals the empirical decisions:
- `ALLOW`: 22
- `FLAG`: 36
- `BLOCK`: 81
- Resulting Strict Recall: 81 / 139 = **58.27%**
- Resulting Loose Recall: (36 + 81) / 139 = **84.17%**

### 2. Forensic Trace & Code Location
The erroneous figures originated from a hand-typed Python dictionary literal in `scripts/export_viz_data.py:193-196`:
```python
"decisions_by_class": {
    "attack": {"allow": 22, "flag": 44, "block": 73},
    "benign": {"allow": 143, "flag": 52, "block": 13},
},
```
This script formatted and exported `viz_data.json`, which was then embedded directly into `docs/BENCHMARK_DASHBOARD.html`.

### 3. Mechanism Analysis & Hypotheses
- **Hypothesis A (Conflated 73 Downgrades)**: Across the evaluated held-out dataset, Policy B executed certified downgrades (`BLOCK` -> `FLAG`) on exactly **73 total prompts** (52 benign prompts + 21 attack prompts). It is hypothesized that the author conflated this total downgrade count of 73 with the attack block count when constructing the static literal.
- **Hypothesis B (Intermediate Uncommitted Run)**: The numbers may have reflected an earlier, unrecorded intermediate evaluation run with different threshold parameters that was never committed to git.

Both hypotheses represent a failure of provenance: manual literals should never be substituted for script-derived log aggregations.

### 4. Remediation & Safeguards
1. **Script Deprecation**: `scripts/export_viz_data.py` has been marked as superseded and modified to exit immediately with an error message.
2. **Closeout Generator**: All closeout metrics and tables are generated by `scripts/eval/generate_review_package.py` and `scripts/eval/closeout_metrics.py` directly from `results/final-v4/predictions.jsonl`.
3. **Automated Audit Test**: `tests/test_dashboard_numbers.py` verifies that every dashboard metric exactly matches `numbers.json`.
